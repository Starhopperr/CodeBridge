## Final report structure

**Front matter:** title page, team details, declaration/certificate if
prescribed, acknowledgement, abstract/executive summary and contents.

1.  **Introduction:** problem, motivation, objectives, users and scope.
2.  **Problem/domain analysis:** evidence, stakeholders, requirements,
    context, assumptions and constraints.
3.  **Existing solutions/literature:** comparable tools, literature,
    prompt approaches and gap analysis.
4.  **Prompt/solution design:** task definition, inputs/outputs, prompt
    architecture, instructions, context, examples, constraints, schema
    and diagrams.
5.  **Prompt development/implementation:** versions, experiments,
    model/tool configuration, prototype and reproducibility.
6.  **Evaluation/testing:** test set, criteria, metrics, comparisons,
    error analysis and failure cases.
7.  **Results/discussion:** measured results, interpretation,
    limitations, reliability and lessons.
8.  **Responsible AI/impact/business/research contribution:** privacy,
    safety, bias, copyright, security and human oversight as relevant.
9.  **Conclusion/future scope:** outcomes, unmet goals and next steps.
    **References/appendices:** cited sources, prompts, test cases,
    evaluation sheets, sample I/O, screenshots and contribution
    evidence.

## Final evaluation

Freeze the test set and rubric before final comparisons. Run the same
inputs against selected prompt versions. Include failures. Report exact
denominators and unrun cases. Compare V1 with final workflow. Separate
model-generated review findings from independently verified defects.
Record model ID, date, settings, prompt version, input and output. Do
not claim universal correctness; state the supported language subset.

## Viva preparation

Create `docs/VIVA_PREPARATION.md` with 15--20 likely questions and
evidence-based answers. Cover P1--P4, prompt chaining, why
constraints/schema are used, semantic equivalence limits, test oracle
design, model configuration, privacy/security, two observed failures and
each member's contribution. Every member should understand the full
workflow.

## LinkedIn blog

Describe the problem, users, prompt-engineering approach, meaningful
iterations, implementation, measured results (including caveats),
limitations, future work and team acknowledgements. Do not publish
private data, secrets, student IDs without approval or unverified
claims.
