# P4 V3 — Production Test Generation Prompt

> [!NOTE]
> **V3 — production/chained workflow.**
> This prompt is the fourth and final step of the automated pipeline (`backend/pipeline.py`).
> It receives the validated outputs of P1, P2, and P3 automatically.
> Its output is validated by Pydantic (`P4Tests` schema) and returned to the user.

---

## System Prompt

```
Design tests for code translation.
Propose normal, boundary, empty-input and algorithm-specific cases based on the source.
Derive expected outputs from the original only when reliable; otherwise mark human
confirmation required.
Include tests targeting review findings.
Do not claim execution.
Return ONLY valid JSON.
```

---

```
Design test cases for the translation from {{source_language}} to {{target_language}}.

Source Language: {{source_language}}

      "test_id": "<TC-001, TC-002, ...>",
      "purpose": "<what this test verifies>",
      "input": "<the exact input to pass to the function/program>",
      "expected_output": "<the expected output or return value, derived from source behaviour>",
      "expected_output_confidence": "<high | medium | requires_human_confirmation>",
      "case_type": "<normal | boundary | empty_input | algorithm_specific | review_targeted>",

    }
  ],
  "coverage_notes": "<explanation of what cases were chosen, what P3 findings are targeted, and any gaps>"
}
```

---

## V3 Improvements Over V2

- **Automated inputs:** All three prior step outputs provided automatically by `pipeline.py`
- **Pydantic enforcement:** Output validated against `P4Tests` schema
- **Targets P3 findings:** `risk_target` field links each test case to a specific P3 finding or marks it as general
- **Confidence field:** `expected_output_confidence` prevents false confidence in analytically-derived expected outputs
- **Low temperature:** Consistent with other steps

## Test Case Type Definitions

| Type | Description | Example |
|---|---|---|
| `normal` | Standard valid input producing expected output | `factorial(5)` → `120` |
| `boundary` | Input at the edge of valid range | `factorial(0)` → `1`, `factorial(1)` → `1` |
| `empty_input` | Empty collection, empty string, zero-length input | `max_finder([])` → `None` / exception |
| `algorithm_specific` | Input targeting a known algorithmic behaviour | Integer division: `divide(7, 2)` → `3` |
| `review_targeted` | Test specifically targeting a P3 finding | P3 flagged integer division risk → test it |

## Expected Output Confidence Guidance

| Confidence | When to Use |
|---|---|
| `high` | Expected output derivable with certainty from reading the source code |
| `medium` | Expected output likely correct but depends on a semantic assumption |
| `requires_human_confirmation` | Expected output depends on runtime behaviour, recursion depth, or platform specifics |

## Schema Reference

See `backend/schemas.py` → `class P4Tests(BaseModel)`, `class TestCase(BaseModel)`.
