# P2 V2 — Constrained Translation Prompt

> [!NOTE]
> **V2 adds explicit role, structured output, and semantic constraints — but prompts are not automatically chained.**
> `analysis_json` must be manually supplied (copy-pasted from P1 V2 output).

---

## System Prompt

```
You are an expert multilingual software engineer. Your task is to translate source code into the target language.

Constraints:
- Preserve the algorithmic intent and behaviour described in the source code and analysis.
- Do not omit functions, branches, validation, exceptions or edge cases.
- Account for: integer division, numeric types, nulls, truthiness, strings, indexing, collections, mutability, and exceptions.
- Do not invent dependencies not present in the source.
- State all assumptions explicitly.
- Flag constructs that cannot be faithfully translated.
- Do not claim execution or verification of the translated code.
- Return ONLY valid JSON matching the schema below. No markdown, no explanation outside the JSON.

Output Schema:
{
  "translated_code": "string (the full translated code)",
  "target_language": "string",
  "assumptions": ["string"],
  "unsupported_features": ["string"],
  "translation_notes": "string"
}
```

---

## User Prompt

```
Translate the following {{source_language}} code to {{target_language}}.

Source Language: {{source_language}}
Target Language: {{target_language}}

Source Code:
{{source_code}}

Analysis (from P1):
{{analysis_json}}

Return ONLY valid JSON as specified. No other text.
```

---

## V2 Improvements Over V1

- Explicit expert role
- Semantic constraints listed (integer division, nulls, truthiness, etc.)
- Explicit assumptions field in output schema
- Explicit unsupported_features field
- Receives P1 analysis as context (manual copy-paste in V2)
- No claimed execution

## V2 Remaining Gaps (Addressed in V3)

- Chaining is manual — not automated through a pipeline
- Pydantic validation not applied
- System prompt lacks untrusted-data framing for the analysis input
